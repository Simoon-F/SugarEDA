# P3 第十二阶段：多页原理图工作区

本阶段补齐类似专业 EDA 的多图纸工作流，但不加入 AI 助手。工程继续统一写入 schema v4，不设置灰度开关，也不引入第二套页面模型。

## 已实现范围

- 顶部图纸页签支持新建、选择、重命名和删除；至少保留一张图纸，单工程最多 128 张。
- 图纸名称限制为 1～96 个安全字符，忽略大小写后必须唯一；Rust 在命令执行和工程打开时做权威校验。
- 元件、导线、网络标签、选择、复制粘贴、拖放、移动和画布诊断全部作用于当前图纸。
- 新增、重命名和删除图纸进入既有 Undo/Redo 历史；切换图纸属于持久化视图状态，不污染编辑撤销栈。
- `.sugeda` 保存全部图纸及 `activeSheetId`，重新打开后恢复当前页。图纸 ID、元件 ID 和导线 ID 在工程内必须唯一。
- 普通元件位号在全部图纸中唯一；DevicePack 多单元符号可以跨图纸共享同一逻辑器件位号。
- ERC 对工程中的每张图纸分别建立电气拓扑并汇总结果。点击其他图纸上的问题会先切页，再选中并定位器件。
- SPICE 网表、探针和仿真检查明确使用当前图纸，避免把互不相连的页面错误合并为同一电路。

## 模块边界

- `src-tauri/src/schematic_sheet.rs`：图纸生命周期、名称/数量/身份约束和当前图纸解析。
- `src-tauri/src/application.rs`：图纸编辑命令、跨页位号分配与 Undo/Redo 事务。
- `src/schematic-sheet.ts`：浏览器预览的纯数据操作和当前图纸解析。
- `src/schematic-tabs.tsx`：只负责页签交互，不包含画布、ERC 或工程存储逻辑。
- `src/schematic-canvas.tsx`：消费当前图纸，不管理图纸生命周期。
- `src-tauri/src/erc.rs`：逐页检查并汇总；`netlist.rs`：只生成当前图纸网表。

这个拆分避免把页签、工程存储、电气检查和 Canvas 绘制堆进同一个组件，后续可分别增加层次端口、页面导航和性能优化。

## 电气语义与限制

普通网络标签仍是单页电气作用域。第十三阶段已经增加显式全局标签、层次化端口和图纸实例；同名普通标签不会因此跨页自动连接。详见 [P3 第十三阶段](p3-phase13-cross-sheet-hierarchy.md)。

第十二阶段交付时，仿真仅解析当前图纸。第十三阶段已改为从当前图纸作为根，展开通过图纸实例或全局标签显式可达的图纸；因此可达范围内的 DevicePack 多单元模型可以聚合绑定，互不连接的独立图纸仍不会被隐式加入仿真。

AI 电路审阅、对话助手和“附带选中电路”等能力本阶段明确延期。它们未来只能消费稳定的只读工程快照和诊断接口，不能成为编辑器数据模型或 ERC 正确性的依赖。

## 下一阶段建议

以上前三项已在第十三阶段完成。后续应增加可复用多实例层次模块、总线、参数化图纸，以及包含数十图纸的跨页性能夹具。

本阶段没有实现 AI、完整 PCB、IBIS/S 参数求解、厂商 SDK 解析或固件/操作系统仿真。
