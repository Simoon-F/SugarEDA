# P3 第十三阶段：跨页网络与层次化图纸

本阶段在 schema v4 上增加显式跨页电气语义，不设置灰度开关，也不加入 AI 助手。所有持久化对象继续使用既有 `Component` 容器，以便复用选择、移动、布线、复制和保存机制；层次规则本身集中在独立模块，Canvas 和 React 工作台不负责判定电气关系。

## 连接对象

### 局部网络标签

`netLabel` 只在所属图纸内连接同名网络。层次展开时，Rust 会为非根图纸的局部名称增加不可见命名空间，杜绝不同图纸上的 `data`、`clk` 等常见名称被意外短接。

### 全局网络标签

`globalLabel` 以明确的工程级名称连接多个图纸。名称必须以字母或下划线开头，只能包含 ASCII 字母、数字和下划线，最长 128 字符。只有显式全局标签会触发跨页连接与仿真可达性扩展。

### 层次端口

`hierarchicalPort` 定义子图纸的稳定端口 ID、名称和方向：`input`、`output`、`bidirectional` 或 `passive`。端口名称在单张图纸内不区分大小写且必须唯一。

### 图纸实例

`sheetInstance` 保存目标图纸 ID，并从目标图纸的层次端口生成引脚快照。新增、删除、重命名端口或重命名图纸后，Rust 会同步所有父图纸实例。删除仍被引用的图纸会被拒绝；双击图纸实例可直接打开目标图纸。

当前一个目标图纸只能被实例化一次。这保证现有工程级位号和逻辑 DevicePack 实例无需复制命名空间即可保持唯一。可复用的多实例子电路需要先引入实例路径位号和参数化覆盖，不能通过复制图块伪装实现。

因此，本阶段会主动从复制/粘贴数据中排除图纸实例块；普通元件和导线的复制行为不受影响。

## ERC 与仿真

Rust `hierarchy` 模块把所有图纸放入互不重叠的内部坐标空间，并建立两类稳定别名：

1. 同名全局标签共享工程级网络名；
2. 父图纸实例引脚和目标图纸端口共享基于实例 ID、端口 ID 的内部网络名。

ERC 在展开后的全工程拓扑上运行。因此跨页连接的电源输出冲突、电压域冲突、必接引脚和差分对规则继续使用同一套检查器。诊断仍返回原始器件 ID，UI 可以切换到实际图纸并定位。

SPICE 以当前图纸作为仿真根，递归包含其子图纸，并包含通过同名全局标签可达的其他图纸。未通过层次实例或全局标签连接的图纸不会被偷偷加入网表。局部标签在非根图纸中自动命名空间化，父子端口使用内部别名，最终网表仍是确定性的平面 SPICE deck。

## 模块边界

- `src-tauri/src/hierarchy.rs`：权威验证、端口同步、循环检测、可达性和层次展开。
- `src/hierarchy.ts`：浏览器预览的数据操作，不替代 Rust 校验。
- `src/hierarchy-navigator.tsx`：只读跨页对象导航。
- `src/schematic-canvas.tsx`：绘制和命中测试，不推断层次拓扑。
- `src-tauri/src/erc.rs` 与 `netlist.rs`：消费展开结果，不管理图纸生命周期。

## 安全与规模限制

- 层次深度最多 32 层，拒绝直接或间接循环。
- 单个目标图纸拒绝重复实例化，拒绝不存在或篡改端口快照的实例。
- 层次连接不读取外部文件、不执行脚本，不改变 DevicePack、SDK Adapter 或模型安全边界。
- 工程仍统一写入 schema v4。
