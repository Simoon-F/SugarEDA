# SugarEDA 0.1 功能体验与手工验收教程

SugarEDA 启动后会显示空白工程。你将亲手画出一个脉冲驱动的 RC 低通电路，生成 SPICE 网表并运行 ngspice。后半部分还会故意制造错误，用来确认错误检查、撤销、保存、打开和模型导入是否正常。

> 本教程对应当前 MVP。界面语言请选择中文。macOS 已在本项目验证；Windows 的打包与干净机器测试仍待完成。

## 1. 完成本教程后能验证什么

- [ ] 桌面应用能够启动，内置 ngspice 显示“仿真器就绪”
- [ ] 元件可以拖入画布、选择、移动、旋转和删除
- [ ] 属性修改会生效，撤销与重做正常
- [ ] 导线可以吸附到绿色引脚，网络标签可以命名节点
- [ ] 正确电路能够生成网表，错误电路会被拒绝
- [ ] 瞬态、工作点、DC 扫描和 AC 扫描能够运行
- [ ] 波形能够缩放、读数、隐藏信号并导出 CSV
- [ ] `.sugeda` 工程能够保存并重新打开
- [ ] SPICE 模型库能够导入并随工程保存

完整体验约需 20～30 分钟。只想先确认核心链路时，做到第 8 节即可。

## 2. 启动正确的应用

在 SugarEDA 项目目录运行：

```bash
pnpm install
pnpm tauri dev
```

必须使用 `pnpm tauri dev` 打开的桌面窗口。`pnpm dev` 只启动浏览器界面预览，浏览器没有权限调用 ngspice、打开工程文件或执行真实仿真。

启动后检查底部状态栏或“设置”页：

- 显示“● 仿真器就绪”：可以继续。
- 显示“○ 仿真器离线”：先执行 `pnpm build:ngspice`，完成后重新运行 `pnpm tauri dev`。
- 已经有可用 ngspice 时，也可以在“设置 → NGSPICE 路径”填写其绝对路径，再点击“检测”。该输入框通常应留空，以优先使用随应用打包的版本。

画布应当是空白的；如果显示了之前保存的电路，请选择“文件 → 新建”。

## 3. 认识这次要画的电路

目标是一个一阶 RC 低通电路：

```text
              R1 1k
       in o---/\/\/\---o out
          |             |
     V1   |            --- C1 1u
   PULSE ( )           ---
          |             |
          +-------------+--- GND
```

参数如下：

| 项目         | 设置值                      | 作用                                           |
| ------------ | --------------------------- | ---------------------------------------------- |
| V1           | `PULSE(0 5 0 1u 1u 5m 10m)` | 每 10 ms 产生一次 0～5 V 脉冲，高电平持续 5 ms |
| R1           | `1k`                        | 1 kΩ                                           |
| C1           | `1u`                        | 1 µF                                           |
| 瞬态步长     | `10u`                       | 每 10 µs 计算一个输出点                        |
| 瞬态终止时间 | `30m`                       | 运行 30 ms，观察三个周期                       |
| 探针         | `v(in); v(out)`             | 查看输入与输出节点电压                         |

时间常数为 `R × C = 1 ms`。因此 `v(out)` 不会像 `v(in)` 一样立即跳变，而应显示平滑的充放电曲线。

## 4. 从空白工程摆放元件

1. 选择顶部“文件 → 新建”。如果询问是否放弃未保存更改，确认后继续。
2. 右侧“文档”区域应显示元件 `0`、网络 `0`。
3. 从左侧元件库依次拖入：电压源、电阻、电容、接地。
4. 按下面的布局摆放。位置不必一模一样，但按照建议坐标摆放会让后续接线最容易。鼠标在画布内移动时，底部状态栏会显示 X、Y 坐标。

| 元件   | 建议中心坐标 | 初始方向   |
| ------ | -----------: | ---------- |
| V1     | X 180，Y 200 | 竖直       |
| R1     | X 340，Y 170 | 水平       |
| C1     | X 460，Y 240 | 先水平放置 |
| Ground | X 320，Y 330 | 接地点朝上 |

放置有两种方式：

- 直接按住元件库中的元件，拖到画布后松开。
- 单击元件库中的元件，再到画布单击一次。按 `Esc` 可取消待放置状态。

画布上每个元件末端的绿色圆点是电气引脚。拖动元件本体可以移动；拖动画布空白处是框选，不是移动画布。要平移画布，请按住空格再拖动，或者使用鼠标中键。

### 检查点 A：放置和选择

- [ ] 画布上存在 V1、R1、C1 和接地，共 4 个元件
- [ ] 单击 R1 后，R1 变成蓝色，右侧属性显示 `R1`
- [ ] 从元件库拖动时没有出现整页文字被选中的蓝色高亮
- [ ] 轻微移动 R1 后，其 X/Y 数值会按 20 px 网格变化

如果刚才移动了 R1，可用 macOS 的 `⌘Z` 或 Windows/Linux 的 `Ctrl+Z` 撤销，让它回到建议位置。

## 5. 设置方向和电气参数

### 5.1 旋转 C1

1. 单击 C1。
2. 点击画布左上方工具栏的旋转按钮，或者右侧属性中的“旋转 90°”。
3. 右侧属性应显示 `90°`，C1 的两个绿色引脚应变为一上一下。

### 5.2 修改参数

逐个单击元件，在右侧编辑“SPICE 参数值”：

| 元件   | 位号 | SPICE 参数值                |
| ------ | ---- | --------------------------- |
| 电压源 | `V1` | `PULSE(0 5 0 1u 1u 5m 10m)` |
| 电阻   | `R1` | `1k`                        |
| 电容   | `C1` | `1u`                        |

输入后按 `Enter` 或单击输入框外部，才会提交修改。位号必须以正确的器件字母开头，例如电阻使用 `R1`，电压源使用 `V1`；同一工程中的位号不能重复。

常用 SPICE 数值后缀：

| 后缀  | 数量级 | 示例    |
| ----- | -----: | ------- |
| `p`   |  10⁻¹² | `10p`   |
| `n`   |   10⁻⁹ | `100n`  |
| `u`   |   10⁻⁶ | `1u`    |
| `m`   |   10⁻³ | `5m`    |
| `k`   |    10³ | `1k`    |
| `Meg` |    10⁶ | `10Meg` |

注意：SPICE 中 `m` 表示 milli（毫），兆应写作 `Meg`，不要用单独的 `M` 表示兆。

## 6. 接线

点击画布左上方的导线工具。每根导线用两次单击完成：

1. 第一次单击起点绿色引脚。
2. 移动鼠标时会显示蓝色虚线预览。
3. 第二次单击终点绿色引脚，导线变为绿色。

移动到终点时会出现一条带直角的预览线。画布右上方可选择：

- `H → V`：从起点先水平、再垂直到终点。
- `V → H`：从起点先垂直、再水平到终点。
- 第一次单击起点后，按 `Tab` 可以在两种转角之间快速切换。
- 右键可以取消当前尚未完成的导线。

选择不会穿过其他元件、也不会与已有线路重叠的方向，可以明显改善布局。

### 6.1 修改已经画好的导线

编辑旧导线时不要进入导线工具，否则单击会开始创建新线。正确操作如下：

1. 切回左上角的“选择”工具（箭头）。
2. 单击已有的绿色导线；被选中的网络会变蓝，所选导线的每段中间会出现橙色方块。
3. 如果只想把类似 `┐` 的走线换成 `└`，使用画布右上方的 `H → V` 或 `V → H`。它会以原来的两个端点重新生成 L 形路径。
4. 如果需要自定义绕开元件，按住某一线段中间的橙色方块，沿该线段的垂直方向拖动。松开后会吸附到网格，并自动补齐必要的直角。
5. 选中导线后也可按 `Tab` 快速翻转 L 形方向；按撤销可恢复编辑前的路径。

整形只改变路径，不移动导线两端，因此原有电气连接会保留。橙色方块是线段控制点，不是新的电气节点。

按照下面顺序画 4 根导线：

1. V1 上方 `+` 引脚 → R1 左侧引脚。
2. R1 右侧引脚 → C1 上方引脚。
3. C1 下方引脚 → Ground 上方引脚。
4. V1 下方 `−` 引脚 → 同一个 Ground 上方引脚。

导线会自动产生直角拐点。第二根线和第四根线看起来可能与示意图略有不同，只要两端准确落在绿色引脚上，电气连接就相同。

### 接线时最容易犯的错误

- 绿色圆点仍清晰露在导线旁边：通常表示没有点中引脚，应撤销后重画。
- 只让两条线在视觉上靠近：不会自动连接。端点必须落在同一个网格点，或者明确落到已有线段上。
- 旋转或移动已经接好线的元件：当前 MVP 不会自动拉伸原有导线，会造成断线。请撤销，然后先摆好元件再接线。
- 一次单击后没有再次单击：导线仍处于预览状态，不会写入工程。

### 检查点 B：导线

- [ ] 右侧“文档”区域显示元件 `4`、网络 `4`
- [ ] 每个非接地元件的所有绿色引脚都有导线到达
- [ ] V1、R1、C1 与 Ground 形成闭合回路

这里的“网络”计数当前实际表示已画出的导线数量，不是合并后的电气节点数量。

## 7. 添加 `in` 和 `out` 网络标签

网络标签把电气节点命名为可读名称，仿真探针 `v(in)` 和 `v(out)` 才能找到它们。

1. 从左侧“连接”分组选择“网络标签”。
2. 把第一个标签放到 V1 上方 `+` 引脚与 R1 左侧引脚所在的导线上。最稳妥的位置是 V1 上方绿色引脚。
3. 选中该标签，在右侧把“网络名称”从 `net` 改为 `in`，按 `Enter`。
4. 再放一个网络标签到 R1 右侧与 C1 上方相连的节点。最稳妥的位置是 R1 右侧绿色引脚。
5. 把第二个网络名称改为 `out`。

标签的锚点最终必须落在导线或引脚上。释放位置距离引脚或导线约 16 屏幕像素以内时，SugarEDA 会自动吸附到精确电气坐标；标签图形与文字可以伸向一侧，但真正的连接点是标签尖端。悬空标签会显示为红色，正确连接后恢复为正常颜色。

### 检查点 C：节点名称

- [ ] 画布上能看到 `in` 和 `out`
- [ ] 右侧“文档”区域显示元件 `6`、网络 `4`
- [ ] 选择两个标签时，右侧“网络名称”分别是 `in`、`out`

## 8. 配置并运行第一次仿真

### 8.1 设置瞬态分析

1. 打开底部“设置”标签。
2. “分析类型”选择“瞬态分析”。
3. 时间步长填写 `10u`。
4. 终止时间填写 `30m`。
5. 探针填写 `v(in); v(out)`。
6. 每次填写后按 `Enter` 或让输入框失去焦点。
7. 确认右侧状态卡显示“仿真器就绪”。

### 8.2 先生成网表

点击顶部运行按钮左侧的“生成网表”图标，然后打开底部“网表”。中间设备行应与下面一致；第一行的工程名称可以不同：

```spice
C1 out 0 1u
R1 in out 1k
V1 in 0 PULSE(0 5 0 1u 1u 5m 10m)
.tran 10u 30m
.end
```

判断方法：

- `0` 是 SPICE 地。
- R1 必须连接 `in` 与 `out`。
- C1 必须连接 `out` 与 `0`。
- V1 必须连接 `in` 与 `0`。

如果网表中出现 `n001` 一类名称，说明对应网络没有正确放置标签。如果生成网表后自动切到“控制台”，先按第 10 节排错，不要继续运行。

### 8.3 运行并检查波形

点击顶部“运行”或按 `F5`。成功时会自动打开“波形”页。

你应该看到：

- `v(in)`：在约 0 V 与 5 V 之间切换的方波。
- `v(out)`：充电和放电都比较平滑的曲线，不会垂直跳变。
- 横轴：0～30 ms 左右。
- 在输入上升约 1 ms 后，`v(out)` 大约达到 3.1 V；约 5 ms 后接近 5 V。这是 1 ms 时间常数的合理结果，不要求像素级一致。

波形页可以继续验证：

1. 移动鼠标，左侧应出现光标时间与各信号读数。
2. 滚轮缩放横轴，拖动波形区域平移。
3. 单击左侧 `v(in)` 或 `v(out)`，可隐藏或恢复该曲线。
4. 点击“适合波形”恢复完整时间范围。
5. 点击“导出 CSV”，保存后用文本编辑器打开。首行应包含时间列和信号列，后面应有大量数值行。

### 核心验收结果

如果网表正确、控制台出现 `Simulation completed`、并且能看到上述两条波形，说明下面这条核心链路已经正常：

```text
原理图编辑 → 电气连接检查 → SPICE 网表 → ngspice → 结果解析 → 波形显示
```

## 9. 验证保存、打开、撤销和重做

1. 选择“文件 → 另存为”，保存为一个新的 `my-rc-test.sugeda`。
2. 选中 R1，把参数从 `1k` 改成 `2k` 并按 `Enter`。标题旁应出现未保存状态。
3. 使用 `⌘Z`/`Ctrl+Z`，R1 应恢复为 `1k`。
4. 使用 `⇧⌘Z`/`Ctrl+Shift+Z`，R1 应再次变成 `2k`。
5. 再撤销到 `1k`，然后保存。
6. 新建空白工程，再通过“文件 → 打开”载入 `my-rc-test.sugeda`。
7. 检查 6 个元件、4 根导线、两个标签和仿真设置是否完整恢复，再运行一次。

### 检查点 D：工程文件

- [ ] 保存后未保存标记消失
- [ ] 撤销和重做都会改变 R1 参数
- [ ] 关闭或切换工程后重新打开，电路与设置没有丢失
- [ ] 重新打开的工程仍能生成相同网表并运行

## 10. 故意制造错误，验证检查机制

每项测试前先保存，出错后用撤销恢复。

### 10.1 删除 Ground

1. 选中 Ground，按 `Delete` 或 `Backspace`。
2. 点击“生成网表”或运行。
3. 应切换到“控制台”，出现类似 `Schematic requires a ground reference` 的错误。
4. 撤销，确认 Ground 恢复。

### 10.2 删除一根导线

1. 单击 V1 与 R1 之间的绿色导线，使其被选中。
2. 按 `Delete`。
3. 生成网表，应出现 `Pin ... is not electrically connected` 一类错误。
4. 撤销，重新生成网表应成功。

### 10.3 制造重复位号

1. 临时再放置一个电阻，默认位号应是 `R2`。
2. 把它的位号改成 `R1`。
3. 生成网表，应出现 `Duplicate reference 'R1'`。
4. 撤销或删除临时电阻。

### 检查点 E：错误处理

- [ ] 缺少 Ground 时不会启动错误仿真
- [ ] 悬空引脚会指出对应引脚
- [ ] 重复位号会被拒绝
- [ ] 修复或撤销后可以再次正常运行

## 11. 继续体验另外三种分析

这一节建立在正确的 RC 电路上。每次修改输入框后记得按 `Enter`。

### 11.1 直流工作点（OP）

1. 把 V1 参数改为 `DC 5`。
2. “设置 → 分析类型”选择“静态工作点”。
3. 探针填写 `v(in); v(out); i(v1)`。
4. 运行后，波形区会改为表格。
5. `v(in)` 与 `v(out)` 应都接近 5 V；稳态电容相当于开路，电源电流应接近 0 A。

### 11.2 DC 扫描

1. V1 保持 `DC 5` 或改为 `DC 0`。
2. 分析类型选择“直流扫描”。
3. Source 填 `V1`，Start 填 `0`，Stop 填 `5`，Step 填 `0.1`。
4. 探针填写 `v(in); v(out)` 并运行。
5. 对这个简单 RC 电路，直流稳态下 `v(out)` 应基本跟随 `v(in)`，得到接近重合的 0～5 V 斜线。

### 11.3 AC 扫描

1. 把 V1 参数改为 `DC 0 AC 1`。
2. 分析类型选择“交流扫描”。
3. Points / Decade 填 `100`，Start Frequency 填 `10`，Stop Frequency 填 `1Meg`。
4. 探针填写 `v(out)` 并运行。
5. 依次点击左侧的“幅值”、`dB` 和“相位”。

正确结果应表现为低通滤波器：

- 低频幅值接近 1 V，也就是约 0 dBV。
- 截止频率约为 `1 / (2πRC) ≈ 159 Hz`。
- 在截止频率附近，幅值约为 0.707 V、相位约为 −45°。
- 高频幅值逐渐下降，相位逐渐接近 −90°。

完成后如需回到最初实验，请恢复 V1 的 PULSE 参数和瞬态分析设置。

## 12. 验证 SPICE 模型导入

这一步只验证模型导入、显示和工程内嵌，不要求搭建新的晶体管电路。

1. 点击左侧“元件库”标题旁的导入按钮。
2. 选择项目内的 `examples/models/learning.lib`。
3. 左侧应新增教学模型，包括 `SUGAR_DIODE`、`SUGAR_NPN`、`SUGAR_NMOS`、`SUGAR_AMP` 和 `SUGAR_FILTER` 等。
4. 将 `SUGAR_DIODE` 拖到画布空白处。右侧属性应显示模型名称和“嵌入模型库”。
5. 撤销该元件，保留已导入的库，然后保存工程。
6. 关闭并重新打开工程，导入的模型仍应出现在元件库中；这说明模型文本已经嵌入 `.sugeda`，不再依赖原始 `.lib` 路径。

这些是教学模型，不是厂商认证的真实芯片模型。RK3576 这类 SoC 也不能通过 ngspice 运行固件或模拟完整芯片；当前范围是电源、阻容网络和兼容的模拟/SPICE 模型。

## 13. 根据你当前截图继续

最初的截图中只有 R1、C1 和 V1，它们都处于未连接状态，而且缺少 Ground。后续截图中的主回路已经连通，但保存文件显示 `in` 标签位于 `(200,160)`，V1 上引脚和导线实际位于 `(200,170)`，两者相差 10 px；因此网表将输入节点命名为 `n001`，探针 `v(in)` 无法找到结果。

可以从截图状态按下面顺序继续：

1. 使用更新后的 SugarEDA 重新打开 `Untitled circuit.sugeda`。
2. 选中红色的 `in` 标签，把它稍微向下拖到 V1 上方绿色引脚或输入导线附近；自动吸附后其 Y 坐标应从 `160` 变成 `170`，颜色恢复正常。
3. 删除画布上可能存在的零长度导线不是必需的；新版本不会再创建这种导线。
4. 再次生成网表，确认出现 `V1 in 0 ...` 和 `R1 in out 1k`，不再出现输入节点 `n001`。
5. 运行瞬态仿真并检查 `v(in)`、`v(out)` 两条曲线。

如果仍从只有三个悬空元件的初始状态继续，则先拖入 Ground、旋转 C1、设置 PULSE 参数，再按照第 6～8 节完成导线、标签和仿真。

如果只是想严格对照教程，也可以选择“文件 → 新建”，从第 4 节重新开始。

## 14. 常见问题速查

| 现象                                    | 最可能原因                                         | 处理方法                                                 |
| --------------------------------------- | -------------------------------------------------- | -------------------------------------------------------- |
| 点击运行后提示 ngspice 不可用           | 使用了浏览器预览，或本地引擎尚未准备               | 使用 `pnpm tauri dev`；必要时先运行 `pnpm build:ngspice` |
| `Schematic requires a ground reference` | 没有 Ground，或导线没有接到 Ground 的绿色引脚      | 放置 Ground，并重新连接其上方引脚                        |
| `Pin ... is not electrically connected` | 导线端点没有命中绿色引脚，或移动元件后导线留在原处 | 撤销移动，删除错误导线后重画                             |
| 找不到 `v(in)` / `v(out)`               | 网络标签缺失、名称拼错或锚点没有落在网络上         | 检查标签值和尖端位置，重新生成网表                       |
| 网表出现 `n001`                         | 节点可连通，但没有被网络标签命名                   | 在该节点精确放置标签                                     |
| 波形只有一条                            | 另一条信号被隐藏，或探针只填写了一个               | 点击左侧信号恢复显示，检查探针并重新运行                 |
| 修改参数后结果没变化                    | 输入框尚未提交                                     | 按 `Enter` 或点击输入框外，再运行                        |
| 接线后移动元件导致失败                  | MVP 尚未自动拉伸导线                               | 撤销移动，或删除相关导线后重新连接                       |
| 拖动元件时整页文字被选中                | 运行的仍是修复前版本                               | 停止旧进程，重新执行 `pnpm tauri dev`                    |
